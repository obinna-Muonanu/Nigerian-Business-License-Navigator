## What these results mean

### What was tested

This is the most important experiment in the project. It answers one question: **does adding the
knowledge graph actually make the agent better?**

The same 15 questions were given to two versions of the agent:

- **Baseline (vector-only RAG):** the agent can only search the documents for paragraphs that look
  like the question, and has to work everything else out from those paragraphs.
- **GraphRAG:** the same agent, with the same documents, search, model and prompt, but it can also
  ask the knowledge graph which steps apply and which must come first.

The **only** difference between the two is the graph, so any difference in the scores comes from the
graph.

The questions fall into three kinds, five of each:

| Category | The kind of question | Example |
|---|---|---|
| **lookup** | One fact from one document | "How much is CAC business name registration?" |
| **multi_step** | A full checklist that draws on many documents, in the right order | "I want to sell packaged zobo in Ibadan. What do I need, and in what order?" |
| **progress** | What's left, given the steps the user has already finished | "I've done my CAC registration. What's next?" |

### How to read the numbers

- **Correctness** and **Citation** are judge scores out of 2, averaged over the five questions.
  2 means fully right (or properly cited), 1 means partly, and 0 means wrong (or no proper source).
- **Order OK** is how many of the five checklists put the steps in a valid order, meaning no step
  comes before something it depends on. Any valid order counts, not just one fixed answer.

Here are the same scores as percentages of the best possible:

| Category | | Baseline | GraphRAG | Difference |
|---|---|---|---|---|
| **lookup** | Correctness | 80% | 80% | no change |
| | Citation | 100% | 90% | slightly lower |
| **multi_step** | Correctness | 40% | 50% | better |
| | Citation | 80% | 90% | better |
| | Order OK | 2 of 5 | 4 of 5 | **twice as many** |
| **progress** | Correctness | 30% | 80% | **much better** |
| | Citation | 30% | 100% | **much better** |
| | Order OK | 3 of 5 | 5 of 5 | **all correct** |

### What the results say

**For simple lookups, the graph makes no difference.** Both agents scored 80% on correctness. That's
what you'd expect: when the answer sits in one paragraph, a plain document search finds it just as
well. The baseline even cited slightly better here (cmp-L5 cost GraphRAG a point for citing a second
source that didn't support the facts). So the graph isn't magic; it only helps where the question
needs connections.

**For full checklists, the graph helps with the order.** Twice as many checklists were in a valid
order (4 of 5, against 2 of 5). Without the graph, the baseline had to guess the order from
whichever paragraphs it found, and often got it wrong. In cmp-M3, for example, it listed only 7
steps when the right answer had 32, and scored 0. Correctness only rose from 40% to 50%, though,
because both agents left steps out. These checklists can run to 25 or 30 steps, and the agent tends
to shorten them to keep the reply readable. The judge counts every missing step against it.

**For "what's next?", the graph makes the biggest difference.** Correctness went from 30% to 80%,
citations from 30% to 100%, and every progress answer was in a valid order. This is where the graph
really shines. To answer "what's left?", the agent has to know every step that applies, remove the
ones already done, and work out which of the rest are now unlocked. The graph does that exactly in
one call. The baseline had to rebuild the whole picture from paragraphs, and it missed steps,
invented agency names (such as "FIRS" instead of NRS in cmp-P4), and in two cases gave no sources at
all.

### It was also cheaper

The same run measured how much work each agent did (from `EXPERIMENT_REPORT.md`):

| | Baseline | GraphRAG |
|---|---|---|
| Document searches across all 15 questions | 32 | 5 |
| Average input tokens per turn | 7,701 | 4,545 |
| Average time per turn | 8.6 s | 8.9 s |

One graph call replaced many separate searches, so the GraphRAG agent sent the model about 40% fewer
tokens per turn, which means lower cost, at almost the same speed.

### The bottom line

The graph earns its place where the brief said it would: **questions that depend on connections
across many documents**, above all "what do I do next, and in what order?". For single-fact
questions it changes nothing, and that's fine, because the document search already handles those
well. The two approaches work best together, which is exactly how the GraphRAG agent uses them.

### Limits to keep in mind

- **Five questions per category is a small sample.** Treat the differences as a clear direction, not
  a precise measurement.
- **The gold answers come from the same graph GraphRAG uses.** I reviewed that graph by hand and
  found it correct, but it does give GraphRAG a home advantage on the planning questions.
- **Both agents still leave steps out of long checklists**, which is why multi-step correctness is
  only 50% even with the graph. Showing the full checklist (in the UI, or in a saved document) rather
  than squeezing it into a chat reply would be the natural next improvement.
- **Scores vary a little between runs**, because the model doesn't answer identically every time.
