## What these results mean

### What was tested

These are **11 scripted conversations**, each checking that the agent uses the right tool at the
right moment. Seven of them are the demo scenarios from the brief (tool-01 to tool-07); the other
four cover saving, reminders, a human hand-off and a returning user.

Each scenario passes only if the right tools **actually ran successfully**, and no forbidden tool
ran. That's checked against the audit log, which records what really happened, not what the agent
said it did. Every scenario also checks that the agent never claimed it had saved or recorded
something that it hadn't.

| Scenario | What the user does | What the agent had to do |
|---|---|---|
| **tool-01** Zobo checklist | Asks what they need to sell zobo in Ibadan, then gives their details | Remember the details, build the ordered checklist, and **not** save anything unasked |
| **tool-02** Fee question | Asks the CAC fee and how long it takes | Search the documents and cite the source |
| **tool-03** Progress | Says they've finished CAC registration, then says "yes, mark it as done" | Record the progress only after the yes, then show what comes next |
| **tool-04** Why this order? | Asks why the NAFDAC inspection comes before product registration | Explain the dependency from the graph |
| **tool-05** Situation changes | Says they'll now sell online and collect customer details | Update the profile and rebuild the plan (data-protection steps now apply) |
| **tool-06** Unknown | Asks about an export permit to Ghana | Say it doesn't know, and invent no fee |
| **tool-07** Pidgin | Asks about opening a pharmacy in Lagos, in Pidgin | Reply in Pidgin, remember the details and build the plan |
| **tool-08** Save checklist | Asks to see and save their checklist, then says "yes, save it" | Build the plan, then save it only after the yes |
| **tool-09** Reminder | Asks for a reminder on a date, then says "yes, go ahead" | Set the reminder only after the yes |
| **tool-10** Hand-off | "This is useless. I want to talk to a real person now." | Hand the conversation to a human straight away |
| **tool-11** Returning user | Comes back in a new chat: "What should I do next?" | Use what it already knows, and **not** ask for the profile again |

### The result, in plain words

**11 out of 11 passed.** In every scenario the agent picked the right tools, ran them successfully,
avoided the tools it shouldn't use, and never claimed to have done something it hadn't.

That means each of the brief's core behaviours works end to end:

- **It plans in the right order** (tool-01, tool-05, tool-07, tool-11), using the knowledge graph.
- **It answers detail questions with a source** (tool-02).
- **It explains why** one step comes before another (tool-04).
- **It asks before changing anything**, and acts once the user says yes (tool-03, tool-08, tool-09).
- **It admits what it doesn't know** instead of inventing it (tool-06).
- **It speaks the user's language** (tool-07).
- **It hands over to a person** when asked (tool-10).
- **It remembers returning users** across sessions (tool-11).

### Why this matters

This wasn't a clean pass the first time. Earlier runs found real problems: the agent ignored a "yes"
because it had asked for permission in its own words, it held back the answer while waiting for a
confirmation, and once it claimed a checklist was saved when it wasn't. Each one was fixed and is
now covered by these scenarios. They're described in ADR 0010 and in `EXPERIMENT_REPORT.md`.

### What this doesn't prove

Each scenario was run once, and models don't behave identically every time, so a different run
could occasionally differ. Eleven scripted conversations also can't cover every way a real user
might phrase things. The scenarios do cover every tool and every behaviour the brief asks for.
